# AttachPlus2 — Typecho 多文件批量上传与管理插件

> **一款专为 Typecho 设计的批量附件上传插件，支持拖拽多选、实时进度、分类管理，让文章写作时的附件处理体验提升一个量级。**

---

## 插件简介

AttachPlus2 是为 Typecho 博客系统打造的**多文件批量上传与管理插件**。它覆盖了文章写作中最常见的附件使用场景：从批量上传多张图片，到拖拽视频、音频、文档等多元化文件，再到一键插入编辑器，所有操作都在写作页面内完成，无需跳转、无需手动切换标签页。

相比 Typecho 默认的单文件上传方式，AttachPlus2 将附件工作流完全重构，带来了**拖拽即上传、批量即管理、勾选即插入**的现代化体验。

---

## 核心功能一览

| 功能 | 说明 |
|------|------|
| **批量上传** | 支持同时选择/拖拽多个文件，自动排队并发上传（最多 3 个并行） |
| **实时进度** | 每个文件独立显示上传进度条，进度一目了然 |
| **多格式支持** | 图片、视频、音频、文档、压缩包、代码文件等均可上传 |
| **类型分组** | 附件按「图片 / 视频 / 音频 / 其它」独立分区展示，互不混淆 |
| **多格式模式开关** | 后台可一键切换：仅图片模式 vs. 全格式支持模式 |
| **一键插入** | 勾选附件后一键插入编辑器，图片自动 Markdown 格式，视频自动 `<video>` 标签 |
| **已插入标记** | 已插入文章的附件显示「已用」橙色标识，避免重复插入 |
| **自动重试** | 上传失败自动重试一次，最终仍失败则提示用户 |
| **附件管理** | 支持在面板内直接删除附件，同时清理数据库和物理文件 |
| **调试模式** | 磁吸调试面板实时记录上传日志，便于排查问题 |
| **新文章兼容** | 未保存的新文章也能正常上传，保存后自动关联附件到文章 |

## 安装方法

### 方式一：直接下载

1. 下载插件源码，将文件夹重命名为 `AttachPlus2`
2. 将 `AttachPlus2` 文件夹上传至 Typecho 的 `usr/plugins/` 目录
3. 进入 Typecho 后台 → 插件 → 启用 AttachPlus2

### 方式二：Git 克隆

```bash
cd /path/to/typecho/usr/plugins/
git clone https://github.com/zizdog/AttachPlus2.git AttachPlus2
```

然后进入后台启用即可。

## 插件配置

启用插件后，点击「设置」进入配置页面：

### 基本设置

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| **单文件最大限制** | 10 MB | 限制单个文件的上传大小，单位为 MB |
| **单次最大上传数量** | 20 个 | 一次上传最多允许的文件数量 |
| **多格式附件模式** | 关闭 | 开启后支持上传所有类型文件；关闭时仅支持图片（JPG/PNG/GIF/WebP/AVIF） |
| **调试模式** | 关闭 | 开启后，在文章编辑页右下角显示磁吸调试面板，记录上传日志 |

### 调试日志管理

配置页面底部提供了日志管理入口：
- 显示日志文件路径、大小
- 一键清除日志，方便定期清理

## 使用教程

### 在文章编辑页使用

启用插件后，进入**写文章**或**写独立页面**页面，编辑器下方会出现 AttachPlus2 上传面板：

```
┌─────────────────────────────────────────────┐
│ 批量附件上传  点击选择文件，勾选后插入          │
├─────────────────────────────────────────────┤
│         📁                                   │
│   点击选择或拖拽文件到此处                    │
│   支持图片/视频/音频/文档等，最多 20 个...    │
├─────────────────────────────────────────────┤
│  [ ] 全选  [ 插入到编辑器 ]  共 0 个           │
├─────────────────────────────────────────────┤
│ 📷 图片                                       │
│ ┌────┐ ┌────┐ ┌────┐                         │
│ │ 图 │ │ 图 │ │ 图 │                         │
│ └────┘ └────┘ └────┘                         │
│ 🎬 视频                                       │
│ ┌────┐ ┌────┐                                │
│ │ 视 │ │ 视 │                                │
│ └────┘ └────┘                                │
└─────────────────────────────────────────────┘
```

### 上传文件

- **点击上传**：点击拖拽区域唤起系统文件选择器，支持多选（Ctrl/Cmd 多选）
- **拖拽上传**：直接从桌面或文件管理器拖拽文件到面板区域，松手即开始上传
- 上传过程中每个文件显示进度条，完成后进度条变为绿色；附件底部默认显示文件名，鼠标悬停时显示「点击选择」提示

### 插入到编辑器

1. 点击已上传的附件缩略图，出现蓝色选中边框
2. 勾选「全选」可批量选中所有附件
3. 点击「插入到编辑器」按钮，自动将内容插入到光标位置

**不同文件的插入格式：**
- **图片**：`![文件名](URL)`（Markdown 标准语法）
- **视频**：`<video src="URL" controls style="max-width:100%"></video>`
- **音频**：`<audio src="URL" controls style="max-width:100%"></audio>`
- **其它文件**：`[文件名](URL)`（Markdown 链接语法）

### 删除附件

鼠标悬停到已上传的附件上，左上角会出现红色「×」按钮，点击即可删除。删除操作会：
- 从面板上移除附件
- 从数据库中删除对应记录
- 从服务器物理路径删除文件

### 已插入标记

已插入文章正文的附件会显示**橙色「已用」标签**，边框变为橙色，方便区分哪些附件已经被使用。

## 技术细节

### 文件类型检测

插件采用**双重校验**机制：
1. **前端过滤**：根据 `multiFormat` 设置，前端 JavaScript 在上传前过滤文件类型
2. **后端校验**：PHP 端通过 MIME 类型和扩展名白名单双重检查，确保安全性

支持的具体格式：

| 类型 | 支持格式 |
|------|----------|
| 图片 | jpg, jpeg, png, gif, webp, avif, svg |
| 视频 | mp4, webm, ogv, mov |
| 音频 | mp3, wav, ogg |
| 文档 | pdf, doc, docx, xls, xlsx, ppt, pptx |
| 压缩包 | zip, rar, 7z |
| 文本 | txt, md, html, css, js, json, xml |

### 新文章附件绑定机制

对于**尚未保存**的新文章，Typecho 默认没有 `cid` 来关联附件。AttachPlus2 通过 Session 机制解决这一难题：

1. 新文章上传时，附件 `parent` 设为 `0`，但 `cid` 被记录到 Session 的 `mu_pending` 队列
2. 当用户点击「保存/发布」时，Typecho 的 `finishPublish` / `finishSave` 钩子触发
3. 插件从钩子中获取文章 `cid`，将 Session 中记录的所有附件一次性绑定到该文章
4. 绑定完成后自动清空 Session，避免污染后续文章

这一过程完全对用户透明，无需手动干预。

### 并发上传控制

上传队列采用**限制并发**策略，最多同时上传 3 个文件，其余文件排队等待。这既能：
- 避免浏览器同时发起过多请求导致性能下降
- 避免服务器因并发处理大量上传请求而响应缓慢
- 给用户更平滑的进度反馈体验

### 自动重试机制

如果某个文件上传失败（网络超时、服务器 500 等），插件会：
1. 将其放入失败队列，继续处理其他文件
2. 所有常规上传完成后，自动对失败队列重试一次
3. 重试后仍失败的，显示黄色提示横幅：`x个附件上传失败（已重试），请检查上传类型或服务器配置！`

## 注意事项

1. **文件大小限制**：请确保 PHP 的 `upload_max_filesize` 和 `post_max_size` 配置不小于插件设置的单文件限制
2. **权限问题**：`usr/uploads/` 目录需要具备写入权限（通常 755 或 775）
3. **多格式模式**：关闭后不仅禁止上传非图片文件，面板上也不会显示任何非图片的已有附件
4. **调试模式**：建议仅在排查问题时开启，调试日志会写入磁盘，长期开启可能占用空间
5. **浏览器兼容性**：拖拽上传和进度条需要现代浏览器支持（Chrome/Edge/Firefox/Safari 最新版本）

## 常见问题（FAQ）

### Q1: 上传后文件没有关联到文章？

对于新文章，请确保**点击保存或发布按钮**。AttachPlus2 的附件绑定是在文章保存钩子中执行的，如果用户只上传了文件但没有保存文章，附件会保持未关联状态（parent=0）。

### Q2: 为什么开启了多格式模式，某些文件还是上传失败？

请检查以下配置：
- PHP 的 `upload_max_filesize` 是否足够大
- `post_max_size` 是否大于等于上传文件的总大小
- 文件扩展名是否在被支持的列表中
- 如果文件是从 macOS/iOS 传输的，某些文件可能 MIME 类型识别不准确

开启「调试模式」后查看磁吸面板中的日志，通常可以定位具体失败原因。

### Q3: 删除附件后，文章中还能访问吗？

不能。删除附件会同时删除服务器上的物理文件。如果文章正文中已经引用了该文件，删除后访问会返回 404。请确认不需要该附件后再删除。

### Q4: 可以在页面模板中直接调用这些附件吗？

可以。AttachPlus2 上传的附件完全遵循 Typecho 原生附件存储机制，存入 `table.contents` 表，类型为 `attachment`。你可以通过 Typecho 的 `Widget_Contents_Attachment_List` 或其他自定义查询来调用。
